# practice — 작업 일지와 현행 상태 (9/23 조장 승인)

세션(사람·Claude)이 자기가 한 일을 잊고 같은 일을 다시 하는 것을 막기 위한 폴더다. 두 겹으로 되어 있다.

| 파일 | 무엇 | 누가 읽나 |
|---|---|---|
| `<파트>/CURRENT.md` | 그 파트의 **현행 상태 한 장** — 지금 유효한 값과 근거 링크, 열린 과제, 알려진 함정 | 세션 시작 때 **반드시** |
| `<파트>/YYYY-MM-DD_<주제>.md` | 그날의 **시행착오 일지** — 시도·실패·막다른 길까지 시간순 | 필요할 때, 포트폴리오 |

파트: `A`(스킬·로봇) · `B`(도징·계량) · `C`(공정) · `D`(HMI·기록). 조장·문서 관리 몫은 해당 파트 폴더에 같이 둔다.

## 세 문서의 역할 분담
- `docs/SOT.md` = **결정**(왜 그렇게 하기로 했나, D-xx). 여기 안 옮긴다.
- `CURRENT.md` = **현행값**(지금 무엇이 맞나). SOT 결정의 결과값과 실측값이 여기 모인다.
- 일지 = **과정**(무엇을 해봤고 무엇이 틀렸나).

## 규칙
1. **시작**: 자기 파트 `CURRENT.md` 와 당일 일지를 읽는다. 값을 주장하기 전에 저장소 원본(`params/*.yaml`, 레시피, 계약 문서)을 **직접** 연다 — 9/23 에 레시피가 40 g 대로 바뀐 것을 모른 채 이틀간 옛 허용폭 22.5 g 으로 계산한 사례가 있다. **`담당` 줄에 자기 이름 뒤 `+ 대행자`가 붙어 있으면(규칙 8) — 복귀한 원 담당자 본인이 이번 세션에서 지운다.** 대행자가 먼저 지우는 게 아니라 원 담당자가 돌아와서 지우는 쪽이 안전하다(대행이 실제로 끝났는지는 원 담당자만 확실히 안다). **문서에 적힌 값·이름은 「어느 코드가 그것을 만드는가」까지 짚는다** — 정의만 있고 생산자가 없는데 거동은 그럴듯해서 안 드러나는 일이 있다(`MATERIAL_EMPTY` 는 정책표가 action 만 올려 **거동이 맞았고**, `DispenseResult.verdict INVALID` 는 담을 값이 없어 `'OK'` 로 떨어지는데 **그 경로가 죽어 있었다**). 둘 다 시험이 통과하고 시연도 돌았고 **기록을 확인할 때만 드러났다** — GMP 는 기록이 곧 산출물이다. **다만 이 목록을 기억으로 만들지 마라** — C 가 9/23 에 네 건이라고 적었는데 확인해 보니 하나는 애초에 불일치가 아니었고(BRD 3.1.3 은 폐기 표시가 이미 달려 있었다) 하나는 전날 고쳐져 있었다(`depth_fraction`, #216). 상세: `practice/C/2026-09-23_조장결정3건_MATERIAL_EMPTY_계약v1.8.md`.
2. **종료**: 일지에 오늘 몫을 추가하고 `CURRENT.md` 를 갱신한 뒤 **커밋·푸시**한다. 스크래치패드·워크트리는 지워질 수 있다(9/22 C 세션 워크트리 3개 소실).
3. **틀린 결론은 지우지 않는다.** 「~~옛 값~~ → 철회 (날짜, 근거 링크)」로 남긴다. 철회 이력이 재작업을 막는다.
4. 일지의 시각은 실제 날짜·시각(KST)이다. 「오전/오후/저녁」으로 적지 않는다. 측정은 CSV 저장 시각(**종료 시각**이므로 소요 시간으로 시작을 역산해 「시작~종료」), 그 외는 커밋·코멘트 시각, 추정은 `≈` 에 구간 근거 병기. 옛 측정을 오늘 재분석했으면 「M/D 측정 · 오늘 재분석」으로 구분한다. **추정치는 자릿수를 가리지 않는다** — `≈14:5x` 가 아니라 `≈14:55`. 가린 자릿수는 순서 오류를 숨긴다: 9/23 에 C 가 대략 표기를 실제 시각으로 바꾸자마자 **순서가 뒤집힌 행 2건**이 드러났다(빌드가 커밋 뒤에, 발견이 실패 뒤에 적혀 있었다). C 가 이 표기를 두 번 썼는데, 규칙이 「추정은 `≈` 에 구간 근거」까지만 적고 있어 **「구간 근거를 붙였으니 지켰다」로 읽혔기 때문이다.**
5. `CURRENT.md` 의 모든 값에는 **근거 링크**(PR·이슈·커밋·yaml 경로)를 붙인다. 링크 없는 값은 미확정으로 본다. **자기 파트가 만드는 값만 적는다** — 다른 파트의 값이나 합산 지표(예: 「gmp_dosing 19 + gmp_process = 205」)는 적지 않고 그 파트 CURRENT 로 링크한다. 규칙 6(코드 PR 이 같은 커밋에서 갱신)은 남의 파트 PR 에는 작동하지 않아 그 줄이 반드시 낡는다(9/23 #271·#273 뒤 C CURRENT 의 dosing 수치가 두 번 못 따라옴). 합산은 필요할 때 각 파트 값을 더한다.
6. **일지**(`YYYY-MM-DD_*.md`)는 docs 전용이라 코드 PR 검토 파이프라인을 거치지 않는다. 하루치를 PR 하나로 올린다. **`CURRENT.md` 는 예외다(9/23 팀장 결정)** — 코드 PR 이 현행값(시험 기준선·정책·상수·계약 버전)을 바꾸면 **같은 PR 에서 자기 파트 `CURRENT.md` 를 함께 고친다.** 따로 docs PR 로 미루면 놓친다(9/23 #257 이 시험 2건을 더했는데 CURRENT 기준선이 181 로 남아 #263 에서 뒤늦게 정정). `docs/interfaces.md` 가 계약을 코드와 같은 커밋에서 고치는 것과 같은 취지다. 정합성 검토는 코드 PR 에서 「CURRENT diff 가 코드 변경과 맞는가」를 본다. 공유 트리 규칙(워크트리만 사용, `add -A` 금지)은 그대로다.
7. 문서 관리 팀장이 주 1회 `CURRENT.md` 를 저장소와 대조한다.
8. **대행 시 충돌 방지**: `CURRENT.md` 는 파트당 한 장뿐이라, 담당자 부재(토큰 소진·자리 비움)로 다른 사람이 그 파트 일을 하면 같은 파일을 모르고 동시에 고칠 위험이 있다. 각 `CURRENT.md` 제목 바로 아래 `**담당**: <GitHub 계정>` 줄을 둔다 — 대행 시작 시 `+ <대행자> (사유·기간)` 을 덧붙인다(GitHub CODEOWNERS·온콜 핸드오프 관행과 같은 목적: 누가 지금 이 파일의 주인인지 파일 자체에서 바로 보이게 한다). **제거는 대행자가 아니라 원 담당자가 복귀 후 자기 세션 시작 때 한다(규칙 1)** — 대행 종료 시점을 스스로 판단해 지우는 것보다 확실하다. 대행자는 **종료(규칙 2) 전에 이 줄부터 확인** — 원 담당자가 같은 시간대에 이미 갱신했으면 병합하고 커밋 하나로 합친다. 편집은 절 단위로 작게 나눠 커밋한다 — 통짜 재작성은 충돌 시 사람이 고르기 어렵다.

템플릿: `TEMPLATE_journal.md`, `TEMPLATE_CURRENT.md`.
