# 원료 반환 시 주기 운동 적용

사용자 제공 `m0609_tw_return_material.drl`의 `return_material_1`은 반환 시작점에서 끝점으로 `movel`한 뒤 `move_periodic`으로 스쿱을 턴다. 원료 2·3도 같은 동작을 적용해 달라는 사용자 지시에 따라 세 원료에 동일한 반환용 진폭·주기·반복 설정을 넣었다. 스쿠핑 후 털기 설정과는 별도로 `stations.yaml`의 `return_shake_*` 값을 사용한다.

`ReturnMaterial`은 시작·끝 TCP 직선 이동 뒤 BASE 주기 운동의 완료를 기다린다. 종료 TCP와 기존 `return_end_posj` 관절각을 확인한 뒤에만 반환 성공으로 기록한다. 후속 스쿱 수납은 기존 관절각 확인을 유지한다. 재스쿱 차단도 반환 끝 이동 시도부터 유지한다. [실행 코드](../../ros2_ws/src/gmp_skills/gmp_skills/execution/scooping.py), [설정](../../ros2_ws/src/gmp_bringup/params/stations.yaml), [계약 설명](../../docs/interfaces.md)

Python 문법 검사와 drawio XML 파싱이 통과했다. `gmp_skills` 전체 단위 테스트 571개도 통과했다. 이 시험은 세 원료의 설정값·이동 순서·BASE 주기 운동 호출과 잘못된 설정·관절각 이탈 시 차단을 확인한다. 새 반환 궤적과 낙하·간섭은 실물에서 아직 검증하지 않았다. 이전 일지의 원료 A/B/C 반환·수납 성공은 **변경 전 끝 관절 이동 방식**의 결과다. [이전 실물 일지](2026-09-29_현장통합_반환수납.md)

## DRL 전체 경로 재대조와 중단

속도 1.0·안정화 10초에서 A 빈 스쿱 87.001 g, 스쿠핑 후 두 번째 유효 계량 149.827 g, 순량 62.826 g이었다. 첫 후계량 162.132 g·std 10.893 g은 무효였다. A 반환·수납은 완료했고 B 빈 스쿱 계량 중 사용자 지적에 따라 실행을 중단·취소 요청했다. B의 완료 계량 결과와 실제 취소 완료는 확인되지 않았다.

DRL 전체 함수 대조 결과 기존 수납 구현에 원본에 없는 scoop ABOVE가 추가돼 있었다. 해당 경유를 제거해 material → return_entry → Z -100 → Y -150 → 열기 → Z +100 순서로 맞췄다. DRL 원본은 A만 털기가 있고 B/C 공통 털기는 앞선 사용자 승인 확장임을 구분한다. 변경 후 실물 재검증 전이다.

이번 실행 결과 CSV와 원시 표본 CSV는 records/2026-09-29_1738_material_return_*.csv에 보존했다. 결과 CSV는 CLI 출력의 소수 3자리이며 원시 표본은 ROS 진단 로그 정밀도를 유지한다. 중단된 B 결과를 만들어 넣지 않는다.
