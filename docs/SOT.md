## 목표

M0609 + RG2 로 **조제 칭량 셀**을 만든다 — 레시피 1건(원료 3종)을 스쿱으로 퍼서 칭량 용기에 분주하고, 로봇 외력으로 무게를 검증하며,
허용 오차 밖이면 일탈로 처리해 HMI 의 QA 판정을 받는다. 9/23 까지 **무인 연속 배치 N회**와 **일탈 자동 처리** 영상을 확보하고, 9/29 시연·9/30 발표.

평가 기준(R12)과의 대응은 `PROJECT_RULES.md` 3-8. 이 프로젝트가 점수를 얻는 곳은 **「기능 동작 지속성」(일탈·복구)** 과 **「입출력 데이터 이해도」(배치 기록 HMI)** 다.

  내부 경로 설정은 `start_from: above`, `arrival: at`이고 MoveToStation 요청은 `approach: 1`이다.
- `stations.yaml: transfers`가 출발·도착 조합과 파지 조건, 티칭 관절각의 단일 출처다.
  두 경로는 아직 **비활성**이다. **실물에서는** 해당 이동을 거부하며 직선 이동으로 우회하지 않는다. **가상 모드는** 활성 여부와 무관하게 기존 직선 이동을 사용하고 보호 목적지 제한도 적용하지 않는다.
  `common.yaml`의 관절 이송 속도·가속도도 0(미확정)으로 두었다.
- 높이 확정: workbench **파지점** `[423,93,100,90,-90,-90]`에서 ABOVE +100/EXIT +200 mm,
  passbox_empty·passbox_done·reject_bin은 AT Z=100에서 ABOVE +50/EXIT +150 mm.
  BASE Z 상대 높이로 계산한다. workbench.posx는 파지 AT로 통합하며 용기 계량은 ABOVE다. 스쿱·원료 접근 높이는 유지한다.
  workbench 출발 AT/ABOVE/EXIT와 passbox_done ABOVE/EXIT 관절각은 반영했다.
  passbox_done AT와 nudge_wait ABOVE 관절각은 **불필요**하다. 제공된 nudge_wait AT 관절각을
  경로 종점으로 사용한다. 넛지 경로에 필요한 티칭값은 모두 입력됐으며 사용자 검증은 남아 있다.
- 출발 AT/ABOVE 관절각·현재 위치 이력·파지 성공 이력과 최신 피드백을 확인한다.
  취소/실패 시 이력을 무효화한다. 스쿱 인출·계량·붓기는 이 변경으로 관절 이동으로 바꾸지 않는다.
- 관절 이송의 통신 계약은 그대로다. 아래 원료 반환 기능은 확정 계약 v1.3에 반영했다. 다른 출발지에서 보호 대상 목적지로 가는 경로도 따로 티칭·등록해야 한다.
- 개발 검증은 **단위 테스트까지만** 수행한다. 가상·실물 검증은 사용자가 담당한다.
  조장·A 담당 티칭과 공정 후속 인계 목록은 `docs/setup.md`의 「관절 이송 티칭·인계」를 따른다.

## 스쿱 계량·초과 반환 (9/19 사용자 승인, 계약 팀 공유 완료)

- `workbench.posx=[423,93,100,90,-90,-90]`는 용기 파지 AT다. `pick_posx`는 제거한다. 용기 계량은 BASE Z +100 mm ABOVE에서 수행한다.
- 스쿱 빈 무게·붓기 전·붓기 후는 해당 원료의 `material_N.posx`에서 잰다. `measure_posx`는 원료 재고 접촉 자세로서 스쿱 계량에 사용하지 않는다.
- 허용되는 스쿱은 `workbench.pour_start_posx → pour_end_posx`로 이동하며 전량 붓고 시작 자세로 복귀한다. 각도만 더하는 부분 붓기는 사용하지 않는다.
- 순 스쿱량이 `max(0, 목표−누적 투입량) + 목표×허용 오차율/100`보다 크면 `ReturnMaterial`로 동일 원료통에 반환하고 시도 한도 내에서 재스쿱한다. 반환 실패 시 공정을 진행하지 않는다.
- 반환은 약통 투입량에 합산하지 않으며 `ScoopCycle`의 `RETURNED=5`/`RETURN_FAILED=6`, `delivered_g=0`, `valid=false`로 남긴다. 기존 빈 스쿱 tare를 유지하므로 반환 후 잔량도 다음 스쿱 계량에 포함된다.
- **9/21 사용자 승인:** 원료 A/B/C의 반환 시작 posx·끝 posx/posj를 입력했다. 시작은 직선 이동, 끝은 손목 특이점을 피하도록 `return_end_posj` 관절 이동 후 유지하며 시작점으로 복귀하지 않는다. 시작 posx·끝 posj가 유효하지 않으면 첫 이동 전에 거부한다. 끝 posx는 참고값이다. 반환 끝→재스쿱 연결은 스쿱 모션 구현 시 함께 처리하며 아직 미검증이다.
- **9/21 배치 변경:** 스쿱·원료통 X=344/439/537 mm 및 제공된 접촉·작업대·넛지·Pass Box·폐기함 좌표를 반영했다. 기존 관절 이송은 비활성을 유지한다. 관절각과 수정된 posx의 일치·경로 간섭은 실물 확인이 필요하다.
- **9/21 반환 후 재스쿱 차단:** 반환 끝 관절 이동 직전부터 _return_rescoop_blocked를 유지한다. 성공·취소·실패 후 후속 Scoop은 첫 이동 전에 거부한다. SafePose·파지 변경으로 자동 해제하지 않으며, 검증된 연결 경로 구현 시 해제 조건을 정한다. 프로세스 재기동은 경로 검증을 대체하지 않는다.
- **C/D 인계 대기:** ReturnMaterial 성공 시 반환 끝 자세에 남고 RETURN 피드백은 발생하지 않는다. docs/interfaces.md의 반환 동작 설명을 v1.5.1로 정정했다. 메시지 필드는 변경하지 않았다. 재스쿱 자동 연속 운용은 새 연결 경로 구현·검증 후 가능하다.
- 계약 v1.3은 9/19 팀 공유 후 9/20 사용자가 팀 승인 완료를 확인하여 확정했다. 계약 확정과 실물 검증은 별개이며, 코드 검증은 단위 테스트까지만 수행한다.

## 계량 표본 간격 (9/20 사용자 승인)

- `common.yaml: scale.period_s=0.82`를 MeasureForce·WeighHeld·WeighContainer의 실제 계량 호출에 적용한다. 기동과 계량 요청 시 유한한 양수인지 검사한다.
- 값은 **표본 읽기 시작 간격의 하한**이다. 센서 호출이 길면 실제 간격도 늘어난다. 0.82초는 9/19 독립 표본 실측에 근거한 시험값이며 동일 성능을 보장하는 값은 아니다.
- 표본 사이 대기는 같은 DSR 워커에서 0.1초 간격으로 외력을 관측한다. 넛지 관측값은 계량 평균·표준편차 표본에 합치지 않는다. 블로킹 장치 호출 동안의 관측 지연은 남는다.
- 20표본이면 표본 시작 구간만 약 15.58초이며 정착·장치 호출 시간이 추가된다. 마지막 표본 뒤 불필요한 간격 대기는 생략한다.
- 개발 검증: 서브에이전트 교차검토 및 관련 단위 테스트 60건 통과. 가상·실물 검증은 미수행이다.
- `min_resolvable_g=19`, gain·offset·표본 수는 유지한다. 새 설정으로 실물 재측정 후 B와 분해능 14 g 적용 여부를 판단한다. B의 `scale_reference.yaml`은 과거 측정 근거로 유지하며 후속 갱신을 인계한다.

## 재기동 시 인출 완료 스쿱 상태 복원 (9/21 사용자 승인)

## 상태·외력 조회 응답 제한 (9/21 사용자 승인)

- **9/21 초기화 응답 문제 후속 승인:** D-01의 기존 클라이언트 사용 예외를 실물 초기화의 모드/툴/TCP 조회·설정, 특이점 처리·BASE 참조 설정까지 확장했다. 벤더는 수정하지 않는다. 툴·TCP가 이미 일치하면 D-10의 수동 전환·재선택을 생략하며 자동 모드(1)는 조회로 확인한다. 불일치할 때만 수동(0)에서 선택한 뒤 자동으로 복귀한다. 설정·조회 응답에 기존 `robot.startup_timeout_s`를 적용하고 자동 재전송은 하지 않는다. 응답 대기 취소는 장치에 전달된 설정 취소를 뜻하지 않는다. 가상 초기화와 일반 동작 호출 전체를 제한 시간 방식으로 바꾼 것은 아니다.

- 이어서 기존 Scoop으로 check_depth를 실행하여 SUCCEEDED와 접근 위치 `[344,-298,260]` 복귀·파지 폭 24.8 mm·grip=true·safety=false를 확인했다. 접촉은 미검출, 최대 관측 Fz 크기 3.124 N, 삽입 깊이 0 mm로 원료 접촉 깊이 검증은 미완료다. 설치된 Python Scoop Goal에는 `material_id`·`attempt`만 있으며 소스의 `depth_fraction`과 빌드 산출물이 불일치한다. 이번에는 공통 필드만 사용했고 계약 재빌드는 하지 않았다.

- `DsrArm.robot_state()`·`tool_force()`는 벤더가 만든 기존 조회 클라이언트를 단일 워커에서 사용하되 응답 대기에 제한을 둔다. D-01의 이번 승인 예외는 이 두 읽기 전용 조회에 한정하며 벤더 파일·ROS 계약은 수정하지 않는다.
- `robot.startup_timeout_s`를 서비스 준비와 응답 대기 각각에 적용한다. 응답 시간 초과 시 future를 취소하고 호출명·대기 단계를 기록한다. 조회 취소는 로봇 정지를 의미하지 않는다.
- 자가진단 미완료·안전 차단 중에는 넛지 외력 조회를 하지 않는다. 외력 감시 실패 및 작업 응답 시간 초과는 차단 상태로 남기고, 진행 중인 작업을 성공 처리하거나 자동 재전송하지 않는다. 명시적 복구 요청은 같은 워커가 처리한다.
- 범위는 상태·외력 조회다. 이동·설정·해제 등 나머지 벤더 호출의 무제한 대기를 모두 해결한 것은 아니며 종료 시 정지·해제 미확인은 계속 실패로 보고한다. 실물 측정 완료와 별개다.
- 검증: 관련 단위 테스트 91건 통과, terra 1명 교차검토 완료. 9/21 실물 재연결에서 `SELF_CHECK OK tool=tool_weight tcp=GripperDA_v1` 및 `RecoverSafety(success=true, manual_required=false, robot_state=1)` 확인. 복구 경로의 힘제어 해제 호출도 성공했다. 이동·개폐·계량은 수행하지 않았으며 실제 통신 장애 주입은 미검증이다.

## 충돌 감도 조회·자가진단 (9/22 사용자 승인, #76)

- 기대 전역 충돌 감도는 **50%**, `common.yaml`의 `safety.collision_sensitivity: 50.0`이 단일 출처다.
- `get_collision_sensitivity`라는 공식 Python 함수는 없다. 공식 C++ `get_safety_configuration()`의
  `_fCollisionSensitivity`를 읽는다. 설치된 DRCF 버전의 반환 구조체를 사용한다.
- D-01 및 벤더 원본 보존 원칙의 승인된 확장: 새 `gmp_dsr_controller` 패키지에서 기존 컨트롤러를 상속하고
  동일한 Drfl 연결로 읽기 전용 서비스를 제공한다. 별도 연결·감도 변경은 없다.
  `robot.launch.py`는 이름을 유지한 채 컨트롤러 종류를 교체하고 기존 벤더 동작을 상속한다.
- `skill_node` 단일 워커의 `DsrArm`만 이 서비스를 직접 호출한다. 실물 기동과 안전 복구 시 툴/TCP·감도를
  확인하고 불일치·조회 실패·시간 초과는 기동 또는 복구 해제를 거부한다. 기존 위치·파지 이력 무효화는 유지한다.
- 계약 v1.7의 내부 서비스 추가이며 C/D 호출 경로·필드는 유지한다. 가상 모드는 실물 감도 확인을 생략한다.
  전역 설정 조회를 실제 충돌 감지 성능이나 로컬 안전 구역 검증으로 해석하지 않는다.
- 실물 조회·컨트롤러 재기동은 아직 수행하지 않았다. 기존 프로세스는 빌드만으로 교체되지 않는다.


## 높이 기반 TW 스쿠핑 (9/22)

- 원료 A의 `m0609_tw_scooping.drl`에서 검증한 `enter → start → tilt → mid → end` spline, shake, BASE 주기 운동, 계량 복귀를 구현했다. `Scoop.depth_fraction`을 워커까지 전달한다. 기존 「check_depth만 구현」 기록을 대체하되 아래 보정 차단을 유지한다.
- 접촉 최초 BASE posx 전체를 내부 결과에 보존한다. 단일 워커가 기존 벤더 `coord_transform` 클라이언트로 BASE↔WORLD를 제한 시간 내 조회한다(D-01 읽기 전용 예외). 기준 자세에서 WORLD 오프셋 `[0,-120,-20]`을 TCP 로컬로 변환하고 접촉 자세의 회전으로 스쿱 끝 WORLD Z를 구한다. TCP Z를 표면 높이로 쓰지 않는다.
- 보정 원본은 `stations.yaml:scooping.A`. 기준 총량100−빈 스쿱35=65 g. 기준 표면72.5 mm는 사용자 범위70~75의 임시 중간값이다. 기준 경로 최저 스쿱 끝 높이와의 차이가 기준 깊이이며 요청 깊이는 그 값×depth_fraction, 예상 순량은65×depth_fraction이다. WORLD Z 평행 이동 후 BASE로 환산하며 원료 부족 시 조용히 제한하지 않고 거부한다.
- **현재 calibrated=false:** BASE=WORLD 가정 시 제공된 근사 오프셋으로 mid 끝 높이48.6 mm가 나와 유격 설명으로 추정한54~55 mm와 차이가 있다(스쿱 끝 직접 실측값 아님). 실제 좌표 변환·오프셋·기준 표면 보정 전에는 첫 이동부터 거부한다. true만 바꿔도 경유점이 바닥50+여유5 mm를 침범하면 거부한다. 이 여유는 실측4~5 mm 중 보수적 값이며 전체 spline 간섭 보장이 아니다.
- `amovesx`는 IDLE+실제 종점으로 완료 확인하며 취소/시간초과/관측 실패 시 정지한다. 털기는 BUSY 이후 IDLE 및 종료 자세를 확인한다. 동작 중 스쿱 끝 하한과 파지를 관측하지만 표본 사이 충돌·팔 전체 간섭은 실물 검증 사항이다. 실패 후 털기/복귀로 진행하지 않는다.
- TW 실물 성공은 사용자 제공 원본 경로에 한정한다. 새 높이 보정 경로는 모의 테스트만 대상이고 로봇 구동·재시작은 하지 않는다. B/C 경로 및 반환 후 재스쿱 연결은 미검증/차단 유지. 용기 wrist 이송(#195)은 이번 범위 밖이다.


### 원료 높이 측정 전용 실행 (9/22)

`skill.launch.py height_measure_only:=true`는 보정 활성 여부와 무관하게 기존 check_depth 측정·정상 복귀만 실행한다. 파지/인출 이력·안전 검사는 유지하며 spline/털기는 하지 않는다. 접촉 최초 BASE 자세를 WORLD로 변환하고 기준 자세에서 구한 TCP 로컬 끝 오프셋으로 접촉 지점의 높이를 계산한다. 로그 및 Scoop Result.message의 HEIGHT_MEASUREMENT_ONLY로 전달한다. 실제 스쿠핑을 하지 않았으므로 success=false / ABORTED로 반환한다. 자동 공정과 동시 사용하지 않는 수동 진단 모드다. 약90 mm의 칼라스톤 표면은 위치별 편차가 있으므로 단일 접촉점을 전체 표면 평균으로 취급하지 않는다. 최초 힘 감지 자세는 통신 지연·돌 재배열·끝 이외 부위 접촉의 영향을 받을 수 있다.
